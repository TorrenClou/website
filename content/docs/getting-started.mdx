## Requirements

- Docker (or Docker Compose) on a machine that can run Linux containers
- At least 2 GB of RAM
- Enough disk space for the torrents you intend to stage — files land on `/data/downloads` before
  being uploaded to your cloud storage, and are deleted automatically afterwards by default

Images are published for `linux/amd64` and `linux/arm64`, so an ARM VPS or Raspberry Pi works out of the box.

## Option 1: One-Command Installer

```bash
curl -fsSL https://raw.githubusercontent.com/TorrentDrive/backend/main/install.sh | bash
```

Windows, in PowerShell:

```powershell
irm https://raw.githubusercontent.com/TorrentDrive/backend/main/install.ps1 | iex
```

It checks that Docker is running, pulls the image, starts the container, waits for `/health/ready`,
and prints the URL to open. **There is no configuration step** — no `.env` to edit and no secrets to
generate by hand. The container creates its own secrets on first boot and stores them in
`/data/postgres/secrets.env`.

Open the URL it prints and [claim your instance](/docs/first-run).

## Option 2: Docker Compose (Zero Config)

Download the root `docker-compose.yml` and bring it up directly:

```bash
curl -fsSL https://raw.githubusercontent.com/TorrentDrive/backend/main/docker-compose.yml -o docker-compose.yml
docker compose up -d
```

## Option 3: 1-Click PaaS Deployment

Deploying on a self-hosted PaaS or managed container platform? Use the dedicated blueprints:

- **[Dokploy](/docs/paas/dokploy)** — includes `template.toml` and `paas/dokploy/docker-compose.yml`
- **[Coolify](/docs/paas/coolify)** — uses `SERVICE_FQDN_TORRENTDRIVE_47100` magic domain variables
- **[Render](/docs/paas/render)** — Infrastructure-as-Code `render.yaml` blueprint
- **[Railway](/docs/paas/railway)** — `railway.json` with persistent `/data` volume

## Manual `docker run`

The installer runs this exact container configuration:

```bash
docker run -d \
    --name torrentdrive \
    --restart unless-stopped \
    -p 47100:47100 \
    -p 127.0.0.1:47200:47200 \
    -p 127.0.0.1:47500:47500 \
    -p 127.0.0.1:47600:47600 \
    -v torrentdrive-pgdata:/data/postgres \
    -v torrentdrive-redis:/data/redis \
    -v torrentdrive-downloads:/data/downloads \
    ghcr.io/torrentdrive/torrentdrive:latest
```

## Ports

| Port | Default Bind | Service |
|------|--------------|---------|
| 47100 | `0.0.0.0:47100` | Web interface (proxies `/proxy/api/*` same-origin to the API) |
| 47200 | `127.0.0.1:47200` | REST API, `/metrics`, and `/hangfire` |
| 47500 | `127.0.0.1:47500` | Grafana dashboards |
| 47600 | `127.0.0.1:47600` | Prometheus metrics |

**Only port 47100 needs to be reachable from outside.** Ports `47200`, `47500`, and `47600` are
bound to `127.0.0.1` by default so administrative dashboards are never exposed on public VPS
network interfaces. Reach them via SSH port-forwarding (`ssh -L 47500:127.0.0.1:47500 user@server`)
or an authenticated reverse proxy.

## Behind a Reverse Proxy

A minimal nginx server block:

```nginx
server {
    listen 443 ssl;
    server_name torrents.example.com;

    # ... your certificate directives ...

    location / {
        proxy_pass http://127.0.0.1:47100;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-Host  $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;

        client_max_body_size 100M;
        proxy_read_timeout   3600s;
    }
}
```

Traefik (including Dokploy and Coolify) and Caddy forward `X-Forwarded-Host` and `X-Forwarded-Proto`
automatically, allowing TorrentDrive to derive its own public URL for Google Drive OAuth callbacks.
