title: AWS S3
description: Upload completed downloads to Amazon S3 or any S3-compatible object storage.
---

## Prerequisites

An AWS S3 bucket (or Cloudflare R2, Backblaze B2, Wasabi, DigitalOcean Spaces, or MinIO bucket) and
an access key pair with read/write permissions.

## Step 1: Create IAM Credentials

Grant your IAM user access to your target bucket:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:AbortMultipartUpload", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::your-bucket-name",
        "arn:aws:s3:::your-bucket-name/*"
      ]
    }
  ]
}
```

## Step 2: Add the Storage Profile in TorrentDrive

1. Go to **Storage** → **Add Storage Profile** → **S3 Compatible**
2. Fill in the connection details:
   - **Profile Name**: e.g. `Primary S3 Archive`
   - **Bucket Name**: your S3 bucket name
   - **Region**: e.g. `us-east-1` (or `auto` for Cloudflare R2)
   - **Access Key ID** and **Secret Access Key**
   - **Endpoint URL** *(optional for AWS S3; required for R2, B2, Wasabi, MinIO)*
   - **Key Prefix** *(optional folder prefix inside the bucket)*
3. Click **Save** — TorrentDrive validates bucket connectivity immediately.

## Resumable Multipart Uploads & Failover

- **Multipart Checkpointing**: Large files are uploaded using S3 multipart streams with part-level
  state tracked in Redis. If the container restarts mid-upload, the worker resumes from the last
  completed part.
- **Health Probes & Failover**: TorrentDrive probes bucket reachability and automatically reroutes
  uploads to another healthy storage profile if an endpoint becomes unreachable (unless the job is
  pinned).

## Security Notes

Credentials are stored in your container's PostgreSQL database on `torrentdrive-pgdata` and never
leave your server — uploads stream directly from your host to your S3 endpoint. See
[Security](/docs/security) for volume protection guidance.
